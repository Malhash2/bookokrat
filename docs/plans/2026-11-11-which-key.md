# Which-Key HUD Implementation Plan

> **REQUIRED SUB-SKILL:** Use the executing-plans skill to implement this plan task-by-task.

**Goal:** Show a transient bottom-right panel listing keymap continuations after the user presses a prefix key (e.g. `<Space>`, `g`) and hesitates — which-key.nvim-style discoverability.

**Architecture:** A new `WhichKeyState` struct owns the menu lifecycle (activate → 300ms delay → visible → dismiss). It is driven by a single post-dispatch hook in `App::handle_key_event` that inspects `App::key_sequence` (a `KeySeq`) after every key: if the accumulated sequence is a keymap prefix, the menu activates and the `KeySeq` clock is *paused* so the sequence stays live while the user reads. Rendering is a bottom-right panel drawn at the end of `App::draw`. Continuations come from a new trie-walk API on `ContextKeymap`.

**Tech Stack:** Rust, ratatui, existing `src/keybindings/` trie keymap, existing `KeySeq` (`src/inputs/key_seq.rs`), SVG snapshot tests (`tests/svg_snapshots.rs`).

---

## Agreed Design (from grilling session — do not relitigate)

1. **Trigger**: automatic on keymap prefix keys, in all contexts routed through `App::handle_key_event` (Global, EpubContent, EpubNormal, Navigation, all popup contexts). Pending states (`f`/`t`/`y`/`m` mark/find) never trigger — they bypass the keymap.
2. **Delay**: 300ms hardcoded constant (`WHICH_KEY_DELAY_MS`). Menu renders only after the user hesitated 300ms. The event loop already ticks every 50ms (`run_app_with_event_source`, `src/main_app.rs:8365`), so the delay renders without new plumbing.
3. **Lifetime**: non-blocking. While visible, the `KeySeq` timeout clock is **paused** (not extended) — sequence and menu share one clock, live and die together. Close paths:
   - any keypress: continuation → executes normally, menu gone; non-continuation → flushed normally, menu gone
   - `Esc`: dismiss menu + abort pending sequence, Esc **consumed** (no side effects like closing popups)
   - mouse click: dismiss menu, click **consumed**
4. **Content**: continuations of the current prefix only, from the keymap trie. Label = existing `Action::description()` (`src/keybindings/action.rs:294`). No new descriptions, no override system.
5. **Position**: bottom-right panel, sized to content, covers a toast notification briefly if one is showing (no coordination needed).
6. **Not configurable.** No settings, no keybindings.yaml entries.
7. **Scope cut (v1)**: PDF standard/normal modes use `pdf_reader`'s own separate key sequence state, not `App::key_sequence`. Which-key v1 does NOT cover PDF modes. Follow-up if wanted.

## Background for the implementer (zero-context notes)

- **Keymap**: `src/keybindings/keymap.rs`. `ContextKeymap` is a trie of `KeyInput` sequences → `Action`. `Keymap` is a `{context: ContextKeymap}` map behind a global `RwLock` (`crate::keybindings::keymap()` returns a read guard-able singleton). `LookupResult` = `Found(Action) | Prefix | NoMatch`.
- **KeyInput / notation**: `src/keybindings/notation.rs`. `KeyInput` = one key. `KeyBinding(Vec<KeyInput>)` = sequence. `format_key_input_display(&KeyInput) -> String` (line ~126) gives the human string (`<Space>`, `<C-d>`, `j`...). `key_event_to_input(&KeyEvent) -> KeyInput` converts events.
- **KeySeq**: `src/inputs/key_seq.rs`. Lazy expiry: `is_expired()` = `keys.is_empty() || last_key_time.elapsed() > timeout` (1s). No active timer — expiry is checked on demand. This is what makes "pausing" easy: a `paused` flag checked inside `is_expired()`.
- **Dispatch sites**: `App::handle_key_event` (`src/main_app.rs:6211`) → `handle_key_event_inner` (6240) → global hotkeys (`handle_global_hotkeys`, 4893), EpubContent block (7074), EpubNormal, popup handlers (`handle_key(key, &mut self.key_sequence)` — popups push prefixes into **App's** `key_sequence`, so a single post-hook in `handle_key_event` sees them all).
- **Event loop**: `run_app_with_event_source` (`src/main_app.rs:8357`). Drains events with `poll(0)`, then every 50ms tick does updates + `needs_redraw` → `terminal.draw`. A 300ms delay therefore becomes visible without any event-loop change.
- **Draw order**: `App::draw` (`src/main_app.rs:4151`) renders background → panels → popups. Which-key panel must be rendered **last** (topmost).
- **Theme**: use `crate::theme::current_theme()` (`Base16Palette`). Existing popups show the convention — read `src/widget/help_popup.rs` render for border/style patterns before writing the render fn.
- **Tests**: SVG snapshots in `tests/svg_snapshots.rs` via `assert_svg_snapshot`. `App::press_key` helper (trait at line 678) calls `handle_key_event`. Test apps via `create_test_app_with_custom_fake_books`.
- **CRITICAL repo rule**: never run `SNAPSHOTS=overwrite` without the user explicitly asking **in that message**. New-snapshot workflow: run test (fails), inspect `tests/snapshots/debug_*.svg`, present to user, let THEM bless.

```rust
/// All bindings that start with `prefix` but are longer than it, collapsed
/// to (next key after prefix, action of the shortest completion).
pub fn continuations(&self, prefix: &[KeyInput]) -> Vec<(KeyInput, Action)> {
    // 1. Walk the trie to the node for `prefix` (return vec![] if absent).
    // 2. For each child edge (key, child):
    //    - if child has an action -> (key, action)
    //    - else recurse: first action found in the subtree, key = the child edge
    //      (display still shows just the next key; description comes from the
    //      eventual action). If the subtree has no action at all, skip.
}
```

On `Keymap` (wrapper, mirrors `lookup`/`is_prefix` at lines 302–316):

```rust
pub fn continuations(&self, context: KeyContext, prefix: &[KeyInput]) -> Vec<(KeyInput, Action)> {
    self.context(context).map(|c| c.continuations(prefix)).unwrap_or_default()
}
```

Notes:
- TrieNode fields are private to this file — the walk is a private recursive helper, fine.
- Dedup: if two deeper bindings share the same next key (e.g. `g` under `g` leading to both `gg` and `gj`), keep the first found; sort output by key display string for stable UI.

```rust
use std::time::{Duration, Instant};
use ratatui::Frame;
use ratatui::layout::Rect;

pub const WHICH_KEY_DELAY_MS: u64 = 300;

/// One menu entry: display key (e.g. "h", "<C-d>") + action description.
pub type WhichKeyEntry = (String, String);

#[derive(Debug, Default)]
pub struct WhichKeyState {
    active: Option<ActiveMenu>,
}

#[derive(Debug)]
struct ActiveMenu {
    entries: Vec<WhichKeyEntry>,
    shown_at: Instant,
}

impl WhichKeyState {
    pub fn activate(&mut self, entries: Vec<WhichKeyEntry>, now: Instant) {
        self.active = Some(ActiveMenu { entries, shown_at: now });
    }

    pub fn dismiss(&mut self) {
        self.active = None;
    }

    pub fn visible(&self) -> bool {
        self.active.is_some()
    }

    /// True once the 300ms hesitation delay has elapsed.
    pub fn should_render(&self, now: Instant) -> bool {
        match &self.active {
            Some(m) => now.duration_since(m.shown_at) >= Duration::from_millis(WHICH_KEY_DELAY_MS),
            None => false,
        }
    }

    /// Render bottom-right panel. Caller checks should_render first.
    pub fn render(&self, f: &mut Frame, area: Rect) { /* Task 4 */ }
}
```

```rust
        self.which_key.dismiss();

    }
```
